# ゆらぐー！ decision log

製品・設計の主要決定と理由。新しい順ではなく決定順。Phase-3 統合ゲート
（Task 16）時点。

## D-01 生命体ファースト — multiplayer より先に「引っ張られる面白さ」を証明

「最初に証明すべきことは、Jevの判断によってスライムがぐにゅぐにゝ引っ張られる
だけで面白いか」。Discord multiplayer は検証後。計画の wave 順（Phase1 生命体 →
Phase2 Jev → Phase3 ローカル → Phase4 multiplayer）に従う。

## D-02 ローカル1画面パーティーを最初の完成形にする

ルーム/WS/再接続の前に、同じ画面を囲んで遊べる `/play` を「遊べる最初の
ビルド」とした。セットアップ→投稿→評価→引っ張り→早期終了/ラウンド終了→
結果→もう一回、の全ループを実 reducer + 実 UI で通す。

## D-03 角ばった統一デザイン — フラットクリーム＋ティール

「せっかくきれいな緑色と角ばった世界観に、最近のウェブ風なのが乗っちゃう」。
暗いグラデーション・ガラス感・丸角カードは禁止。全 UI を chamfered（角切り
落とし）の2層プレート（ティール縁＋アイボリー面）＋ハードオフセット影に統一。
drop-shadow 8方向ハックは片側だけ枠が出る事故のため廃止、実測 SVG パスで
全周均一の輪郭を引く。

## D-04 座席＝アトラクター

プレイヤーは「変な位置」ではなく、生命体が引っ張られる先のポストに座る。
seat chip がアトラクターマーカーに付くので「誰がどの選択肢を引っ張るか」が
空間で読める。chip には担当選択肢（ねらい）を併記。

## D-05 吹き出しは動かさない — 座席と生命体の間に静止ポップ

移動する吹き出しは読めない。投稿者の座席と生命体の間（内向き）にポップイン→
約4.5秒静止→消去。20px・最大3行。尾は `atan2(座席−吹き出し中心)` の実測で
常に座席を向く。

## D-06 確率は表示しない — 身体で見せる

HUD は担当スロット・誰の番か・ラウンド・deadline バーのみ。分布は生命体の
姿勢・傾き・葛藤で表現する（パーティー中に数値を読ませない）。

## D-07 IME安全入力＋grapheme上限

Enter は composition 中・確定 Enter（keyCode 229）で絶対に送信しない3重ガード。
上限は UTF-16 length ではなく `Intl.Segmenter` grapheme 140。pending→ack で
入力クリア、二重送信防止。

## D-08 早期終了は「連続支配 streak」— 吸着リングは廃止

「吸着リング＝終了みたいになっちゃうのは違う。ほぼ決まっても数ターン猶予を
持たせるべき」。同スロットが grace=3 連続で明確に支配（top-2 差 ≥0.15）した
評価が出た時だけ dwell-complete。拮抗評価は streak リセット。adhering 表情・
リングは演出不要として撤去し、`adhere` は reducer bookkeeping に留める。

## D-09 LocalLoop は epoch ガードの命令型ホスト

React 非依存の reducer 駆動ループ。rematch は epoch++ で飛行中評価・全タイマー
を無効化し arena 全体を remount。`adhere` 再報告は支配 step ごと（受理投稿で
reducer 側 adhesion が消えるため、再報告しないと dwell が二度と発火しない
バグになった）。

## D-10 ローカル TURN スロットは 300 秒

1画面パーティーで壁時計レースはさせない。deadline が試合を乗っ取らないよう
`LOCAL_TURN_SECONDS=300`（コア default 30s は据え置き）。

## D-11 決定的 mock provider — e2e は fixture で勝者を独立検証

`favor-<choiceId>` は投稿者自身のスロットを 0.7 で支持 → 勝者は「最後に
評価が着地した投稿者」になることが fixture から分かる。`?eval=live` で
実 Jev、`?failEval` `?evalDelay` で障害パスを検証する。

## D-12 入力 dock は下端接地のゲームトレイ

「下の入力欄のデザイン、配置が終わってる」→ 中央浮きフォームを廃止し、画面
下端にフラット接続する角ばったトレイに再設計。3ゾーン（行動席＋ねらい /
フレーム付き入力 / 送信）＋左端スロット色スパインで「誰の番」を即判別。

## D-13 パーティー距離で読める文字階層

最小実用サイズを底上げ：HUD 番名 16px・座席名 15px・吹き出し 20px・
入力 16px・feed 14px・補助 12.5px まで。離れて見ても読めることを優先。

## D-14 シナリオ・目標は常時表示

「シチュ・自分の目標が画面に出てこないと困る」。シナリオ strip（HUD下左上）、
座席 chip のねらい、dock の `ねらい：` 表示を常設。

## D-15 狭幅は情報の重複を削る — roster は座席に譲る

375px 級では HUD 折り返しが座席・strip と衝突する。roster chip は 1040px 未満で
記号のみ、640px 未満で非表示（座席 chip が名前・色・ねらい・番パルスを持つため
情報は失われない）。dock も2行化し、シナリオstripは 32%/60% の上限で上座ゾーンに
届かないよう制限する。
